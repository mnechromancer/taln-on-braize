# CLAUDE.md

## Source of truth

`docs/core-systems-spec.md` is authoritative for gameplay numbers and system behavior. If a handoff step disagrees with the spec, flag the conflict instead of picking one.

## Living docs

`docs/roadmap.md` and `docs/core-systems-spec.md` are living documents. Expand them as the work needs, through the whole project lifecycle; don't treat either as a fixed scope list.

- When work needs something the roadmap doesn't list, add a row in the right phase (with its milestone ID and status) in the same commit as the work. Pulling later-phase work forward is fine when the current phase's gate needs it; say so in the row.
- When work needs behavior or numbers the spec doesn't define, or changes ones it does, add a §15 revision row (Change | Where | Why) in the same commit. Start a new version heading for each new batch of revisions.
- This covers scope and clarifications. A change to design intent, or a contradiction with the spec, Art Direction or Narrative Bible, still goes to the user as a flagged decision rather than being written in.

## Conventions

- Use statically typed GDScript everywhere.
- Hard-code no gameplay numbers. They go in `@export` fields on tuning Resources, saved as `.tres` files under `game/data/tuning/`.
- Systems talk to each other through signals.
- Physics runs at 60 Hz, with 3D physics interpolation enabled in the project settings.
- Input actions are defined only in `game/tools/setup_input_map.gd`. Edit the table there and rerun it rather than editing `[input]` in `project.godot`. Gamepad A is bound only to what it was reserved for, Welcome the Agony and Catalyze (`welcome`, `catalyze_commit`); paused menus also confirm with it through Godot's built-in `ui_accept`.
- Meta state (caps, banked Agony) lives in the `MetaState` autoload, saved to `user://meta.json`; the cycle (seed, Returns, stations) in the `CycleDirector` autoload. Reach them with `Meta.state()` and `Cycle.director()`, not the autoloads' global names: `--script` runs compile scripts before autoloads exist. Check and bot scripts call `Meta.state().redirect(...)` first so they never touch the player's file.
- `game/scenes/graybox_station.tscn` is generated by `game/tools/build_graybox_station.gd`. Rerunning the builder overwrites hand edits to that scene.

## C++ (GDExtension)

SwarmServer (with its FlowField), MoteServer, SwarmType, SwarmTuning and MoteTuning live in `src/swarm/`. For debug builds, run `scons target=template_debug dev_build=yes` from that folder. It writes `game/bin/libswarm.windows.template_debug.x86_64.dll`; the SConstruct drops dev_build's `.dev` suffix so `swarm.gdextension` finds one name. Keep `reloadable = true` in `swarm.gdextension`. If Windows refuses to overwrite the DLL while the editor is open, close the editor, build, and reopen. Don't try to work around it.
